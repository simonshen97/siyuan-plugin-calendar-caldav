## 1. 安装

### 1.1 从集市安装（推荐）

思源 → 「设置 → 集市 → 已下载 → 安装包」，选择本插件压缩包即可。

### 1.2 手动安装

1. 解压发布包，得到目录 `siyuan-plugin-calendar-caldav/`（**压缩包内已经是这个唯一顶层目录**，直接解压即可）；
2. 把整个目录放到工作空间的 `data/plugins/` 下（**目录名必须与 `plugin.json` 的 `name` 完全一致**）：

   ```
   <工作空间>/data/plugins/siyuan-plugin-calendar-caldav/
   ```

3. 思源 → 「设置 → 集市 → 已下载」→ 启用插件（或重启思源）。

### 1.3 Docker / 浏览器版

Docker 版的工作空间通常在容器内的 `/siyuan/workspace`，把插件目录放进去即可：

```bash
docker cp siyuan-plugin-calendar-caldav <容器名>:/siyuan/workspace/data/plugins/
```

或者挂载卷时直接放在宿主机的对应目录：

```
<宿主机工作空间>/data/plugins/siyuan-plugin-calendar-caldav/
```

放好后**重启容器**（或「设置 → 集市 → 已下载」里刷新）。

> **「集市包清单文件缺失」是怎么回事？**
> 这是思源内核的包结构校验报错（`kernel/bazaar/local.go`）：
> 它要求**清单文件（`plugin.json`）位于压缩包根目录，或位于「唯一的顶层目录」内**。
> 如果压缩包是「扁平结构」（`plugin.json` 与 `i18n/`、`README.md` 等并列在根），
> 或解压后多套了一层目录（例如 `xxx/siyuan-plugin-calendar-caldav/plugin.json`），
> 本地安装（Docker 版尤其容易遇到）就会报这个错。
> 本插件从 **v0.6.7** 起按规范打包（唯一顶层目录），并且 `scripts/zip.mjs`
> 与 `scripts/check-consistency.mjs` 都会在打包时校验该结构，防止回归。

> **「该插件不支持在当前终端上使用」是怎么回事？**
> 这是思源客户端拿**当前前端**去比对清单里的 `frontends` 白名单，不匹配就拒绝启用
> （判定逻辑在 `kernel/bazaar/plugin.go` 的 `IsIncompatiblePlugin`）。
> 容易踩的坑：**思源并没有 `browser` 这个前端取值**——合法值只有
> `desktop`（桌面）、`desktop-window`（桌面新窗口）、`mobile`（移动端）和
> `all`（全平台）。写成 `"browser"` 会永远匹配不上，Docker 走浏览器访问时就会报这个错。
> 本插件从 **v0.6.8** 起声明 `frontends: ["all"]`，桌面、桌面窗口、移动端与 Docker 浏览器访问都能通过；
> `src/plugin-manifest.test.ts` 与 `scripts/check-consistency.mjs` 都会拦截非法取值。

### 1.4 从源码构建

```bash
npm install

node scripts/build.mjs     # 编译到 .package/siyuan-plugin-calendar-caldav/
node scripts/zip.mjs       # 生成 .package/siyuan-plugin-calendar-caldav.zip
```

其它可用脚本：

| 命令 | 作用 |
| --- | --- |
| `node scripts/dev.mjs` | 监听源码变化并增量构建 |
| `node scripts/check-consistency.mjs` | 一致性检查（中英文语言包键对齐、无死代码等） |
| `npx tsc --noEmit` | 类型检查 |
| `npx vitest run` | 单元测试 |

要求 Node.js 18+（推荐 20 / 22）。

## 2. 快速开始

以最常见的三类服务为例。

### 2.1 Nextcloud / Radicale / Baikal / iCloud（标准 CalDAV）

1. 打开日历面板 → 底部「**设置**」→「**添加 CalDAV 账户**」页签；
2. 填写：

   | 字段 | 说明 |
   | --- | --- |
   | 名称 | 任意，用于区分账户 |
   | 服务器地址 | 服务商的 CalDAV 根地址，例如 `https://cloud.example.com/remote.php/dav` |
   | 用户名 | 通常是登录名或邮箱 |
   | 密码 / 密钥名称 | 见下方「凭据怎么填」 |

3. 点「**测试连接**」→ 成功后点「**发现日历**」；
4. 回到日历面板，侧栏会列出所有日历，勾选要显示的即可。

**凭据怎么填**（两种方式，任选其一）：

- **密钥名称（推荐）**：先在「思源设置 → 密钥和变量」里新建一个密钥，把**密钥名**填到这里。
  密码不会落进插件配置，导出配置分享时也不会泄露。
- **密码**：直接填。注意这会把密码明文保存在插件配置里。

> iCloud / Fastmail / QQ 邮箱 / 企业微信等服务要求使用「**应用专用密码**」或「**邮箱授权码**」，
> 直接填登录密码会认证失败。

### 2.2 QQ 邮箱

QQ 邮箱不返回日历集合列表，需要手填集合地址：

| 字段 | 值 |
| --- | --- |
| 服务器地址 | `https://dav.qq.com/calendar/` |
| 用户名 | 你的 QQ 邮箱地址 |
| 密码 | QQ 邮箱设置里生成的**授权码** |
| 手动指定日历集合地址 | `https://dav.qq.com/calendar/<你的邮箱>/<日历名>/` |

集合名是一串不透明的 ID（例如 `F23EXAMPLEopaque~i~8zRqAQAS`），可以从手机端同类 App 的配置里抄。
**注意：波浪号 `~` 要原样保留**，替换成 `%7E` 会失败。

### 2.3 企业微信

| 字段 | 值 |
| --- | --- |
| 服务器地址 | `https://caldav.wecom.work/calendar/` |
| 用户名 / 密码 | 企业微信账号与密码 |

企业微信对根路径返回 403 + HTML，插件会自动尝试 `/.well-known/caldav` 找到真正的 CalDAV 根。

### 2.4 Vikunja

Vikunja 是**只有任务（VTODO）、没有日程（VEVENT）**的服务：

| 字段 | 值 |
| --- | --- |
| 服务器地址 | `http://<主机>:<端口>/dav/projects/<项目ID>/` |
| 用户名 / 密码 | Vikunja 账号，**推荐用 API Token**（开启了 2FA / OIDC 的账号必须用 Token） |

因为只支持任务，往这类日历推送**日程**会被自动跳过（日志里会写明原因），这是预期行为。

## 3. 界面与操作

### 3.1 打开日历

三种入口：

- 顶部栏的日历图标；
- 停靠栏（右侧）的日历面板；
- 命令面板：`打开日历视图`、`立即同步日历`、`新建日历事件`（默认无快捷键，可在「设置 → 快捷键」里自行绑定）。

### 3.2 侧栏（日历列表）

- **勾选** = 显示 + 参与同步；**取消勾选** = 停用（不显示、也不发任何请求）；
- 停用的日历会收到折叠区「**已停用（N）**」里，随时可以勾回来；
- 侧栏里的勾选是**逐个日历**的开关，状态会**持久化**，重启思源后保持。

> 注意区分：设置页账户卡片里的「启用」控制的是**整个账户**，侧栏勾选控制的是**单个日历**。

### 3.3 日历底部栏

| 按钮 | 作用 |
| --- | --- |
| **同步** | 按「同步 → 默认同步方向」执行一次同步 |
| **刷新** | 只重新拉取当前视图范围内的数据（强制忽略缓存） |
| **设置** | 打开设置对话框 |

打开「高级 → 调试模式」后，「同步」会拆成三个按钮，便于分段排查：

| 按钮 | 作用 |
| --- | --- |
| **写入** | 只把 CalDAV / 思源数据源的内容写入思源（数据库行或文档） |
| **拉取** | 只把思源里的改动推回远端 |
| **同步** | 完整双向（等同原来的「同步」） |

### 3.4 事件操作

- **新建**：在日期格上点击/拖选，或命令面板「新建日历事件」；
- **编辑**：点击事件打开编辑器（标题、开始/结束、全天、重复、提醒、地点、链接、描述）；
- **拖动**：拖动事件改时间（需要目标日历可写）；
- **跳转**：从事件详情跳到对应的思源条目。

## 4. 设置项逐项说明

设置入口：**日历面板底部 →「设置」**。共 6 个页签。

> 所有修改**即时写入内存并在关闭对话框时保存**，改完直接生效。

### 4.1 添加 CalDAV 账户

**页签作用**：管理 CalDAV 账户，并发现它们下面的日历集合。

每个账户是一张卡片，卡片内字段：

| 字段 | 说明 |
| --- | --- |
| **名称** | 账户显示名。它会作为「**来源列**」的值写进数据库，建议起个能区分的名字（如「QQ 邮箱」「企业微信」「Vikunja」） |
| **服务器地址** | CalDAV 根地址。插件会先直接访问它；若返回 403，再自动尝试 `/.well-known/caldav` 重定向 |
| **用户名** | CalDAV 登录名（通常是邮箱） |
| **密码** | 明文密码 / 应用专用密码 / 授权码。保存在插件配置里 |
| **密钥名称（推荐）** | 改用「思源设置 → 密钥和变量」里的密钥名，密码不落盘 |
| **认证方式** | `Basic`（默认）或 `Bearer`（API Token，Vikunja 等） |
| **启用** | **整个账户**的总开关。关闭后该账户下所有日历都不可见、也不发请求 |
| **手动指定日历集合地址** | 逗号/换行分隔的集合地址列表。用于服务端不支持发现流程时（QQ 邮箱必须用） |

卡片内的按钮：

| 按钮 | 作用 |
| --- | --- |
| **测试连接** | 只验证地址与凭据是否可用，不保存日历 |
| **发现日历** | 按标准流程（当前用户 principal → calendar-home-set → 列举集合）找出所有日历 |
| **删除账户** | 删除账户，并清理它名下的同步映射 |

**提示**：`启用` 是账户级开关，与侧栏的逐日历勾选**不重复**、作用域不同。

### 4.2 思源数据源

**页签作用**：把思源自己的数据当成日历数据源（**只读**，不会反向改动你的数据）。

| 按钮 | 说明 |
| --- | --- |
| **绑定数据库（属性视图）** | 选一个数据库块，用它的**日期列**作为日历时间轴；每个行 = 一个事件 |
| **添加 SQL 查询源** | 写一条 SQL，用结果集当作事件列表 |

**绑定数据库时需要的字段**：

| 字段 | 说明 |
| --- | --- |
| **数据库 ID** | 属性视图 ID，或数据库**所在块的 ID**（两种都能填，插件会解析） |
| **日期字段** | 日历排布依据（必填） |
| **标题字段** | 事件名称的来源列 |
| **检测字段** | 读取该数据库的所有列，填充上面的下拉框 |

**添加 SQL 查询源时需要的字段**：

| 字段 | 说明 |
| --- | --- |
| **SQL 语句** | 例如 `SELECT * FROM blocks WHERE type = 'd' AND ial LIKE '%custom-due%'` |
| **开始日期属性（custom-\*）** | 结果集中哪一列/属性作为开始时间 |
| **结束日期属性（可选）** | 结束时间来源 |

**重要约定**：思源数据源是**只读**的。日历上对这类事件做修改不会写回思源数据库。

### 4.3 数据库同步

**页签作用**：把各来源的事件**写成思源数据库块（属性视图）的行**，用一个带日历视图的数据库统一管理全部日程。

这是本插件最强大的功能，也是配置最细的一项。

#### 4.3.1 基本配置

| 字段 | 说明 |
| --- | --- |
| **数据库块 ID** | 目标数据库所在块的 ID。在数据库块上右键 →「复制块 ID」（形如 `20240118120204-kwyzf77`） |
| **读取字段** | 解析该数据库的全部列，下面各下拉框才有选项。**读取成功且已绑定日期列时，会自动启用本页签** |
| **启用数据库同步** | 本功能的**总开关**。关闭时同步只读远端，**不会写入数据库**（日志里会显示 `target=read-only`） |
| **同步方向** | `只读汇总：远端 → 数据库`（推荐，数据库是汇总视图）／`双向：数据库改动也会推回远端` |

> ⚠ **开关陷阱**：如果数据库已绑定、日期列也选好了，但「启用数据库同步」没勾，
> 同步会跑得很正常却**一行都不写**。设置页顶部与读取结果处都会给出醒目警告。

#### 4.3.2 字段绑定

「读取字段」成功后逐项匹配。**只写入已绑定的列，未绑定的列永远不会被改动。**

| 绑定项 | 写入内容 | 建议 |
| --- | --- | --- |
| **日期列** | 事件开始时间 | **必填**，日历视图按此列排布 |
| **标题列 / 事件名称** | 事件标题 | 建议绑定（文本列） |
| **结束时间列** | 事件结束时间 | 可选 |
| **描述列** | 事件描述 | 可选 |
| **地点列** | 事件地点 | 可选 |
| **来源列** | 账户名称（或数据源名称） | 建议绑定，用于在一个数据库里区分 QQ / 企业微信 / Vikunja |
| **唯一标识列** | 远端 UID | 可选，便于人工核对 |
| **插件标识列** | `caldav:<远端 UID>` | **强烈建议绑定**，见下 |
| **状态列** | 任务状态文本（如 `NEEDS-ACTION`） | 可选；**不要绑定到复选框列**（勾选框无法表达多状态，会被自动跳过） |

#### 4.3.3 「插件标识」列（重要）

插件靠这一列判断「**哪一行是我写的**」：

- **有值**且以 `caldav:` 开头 → 该行由插件管理，可以被更新/删除；
- **为空** → 你手写的行，**永远不会被覆盖或删除**；
- 顺便还能一眼看出该行对应哪个远端事件。

**怎么配**：

1. 在数据库里**新增一列**，名字随意（建议就叫「插件标识」），类型选 **文本**；
2. 「读取字段」→ 把「插件标识列」绑定到它。

> 不绑定该列也能用，插件会退回「读行块自定义属性」的老方式。
> 但新行创建瞬间可能还没进思源的块树索引，导致写属性失败（内核报 `tree not found`），
> 那几行就会变成「不认识」的孤儿行。**所以请绑定。**

> 另外：数据库行是**游离块**，删除行 = 删除块，请自行做好数据备份。

### 4.4 同步

**页签作用**：控制同步方向、范围、冲突策略与落库方式。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| **默认同步方向** | `双向` | `双向` = 两边互相同步；`CalDAV → 思源` = 只读远端；`思源 → CalDAV` = 只上传；`不同步` = 关闭同步 |
| **冲突处理** | `两者都保留（另存副本）` | 两边都改过同一事件时的策略：`以远端为准` / `以本地为准` / `两者都保留（另存副本）` / `跳过` |
| **同步过去天数** | `90` | 往前拉取多少天（0–3650） |
| **同步未来天数** | `180` | 往后拉取多少天（0–3650） |
| **自动同步间隔（分钟，0 为关闭）** | `15` | 定时同步周期；`0` 关闭 |
| **文档落库路径模板** | `/日历/${yyyy}/${MM}` | 选择「落库笔记本」后，事件写成文档时的路径模板。可用 `${yyyy} ${MM} ${dd} ${title}` |
| **落库笔记本** | *（空）* | **不选 = 只读远端，不写入思源文档**；选了才会把事件写成文档 |
| **把没有远端对应物的思源条目推送到远端** | 关 | 打开后，思源里新增的、没有远端映射的条目会被推成远端事件。默认关闭（避免误推） |
| **远端事件被删除时，同时移除思源条目上的同步属性** | 关 | 打开后远端删除会同时清理思源条目上的同步属性；关闭则只解除映射 |

## 5. 工作原理

```
┌────────────┐   HTTP(S)    ┌──────────────┐
│ CalDAV     │◀────────────▶│ 思源内核      │
│ 服务端      │              │ forwardProxy │
└────────────┘              └──────┬───────┘
                                   │ 插件 API
                            ┌──────▼───────┐
                            │ 本插件        │
                            │  · CalDAV 客户端
                            │  · iCalendar 解析
                            │  · 同步引擎
                            └──────┬───────┘
                                   │ 内核接口
                     ┌─────────────┴─────────────┐
                     │                           │
              ┌──────▼──────┐            ┌───────▼───────┐
              │ 数据库块     │            │ 思源文档       │
              │（属性视图行）│            │（每事件一篇）  │
              └─────────────┘            └───────────────┘
```

### 为什么请求必须经内核转发

思源插件运行在 Electron 渲染进程里，直接 `fetch` 跨域 CalDAV 地址会被 CORS 拦住，且无法访问
系统证书库。因此所有 CalDAV 请求都通过内核的 `/api/network/forwardProxy` 发出。

### 同步是怎么判定变更的

- 每个「远端事件 ↔ 思源条目」的对应关系保存在**同步映射**里；
- 远端用 `ETag` + 内容哈希判断是否变化；思源侧用投影哈希判断；
- 冲突（两边都改）按「同步 → 冲突处理」决定；
- **窗口守卫**：只有落在「过去 N 天 ~ 未来 M 天」内的事件参与同步，窗口外的事件不会因为「看不到」而被当成删除；
- 远端资源返回 **404/410** 时判定为「远端已不存在」，自动改为**新建**（自愈），而不是无限重试更新。

## 6. 多应用兼容策略

不同服务端对 CalDAV / iCalendar 的实现差异很大，插件为此做了多层兜底。

### ① 支持任务（VTODO）

Vikunja 这类服务端**只有任务、没有日程**。插件会：

- 读取 `supported-calendar-component-set`，识别日历支持 `VEVENT` 还是 `VTODO`；
- 解析 `VTODO`（含 `DUE` 回退、`STATUS`、`PERCENT-COMPLETE`）；
- 只支持任务的日历**不会**被推送日程（日志写明「该日历只支持任务，无法写入日程」），避免误写。

### ② 事件拉取：多层请求策略

对同一个日历依次尝试，命中即缓存该变体：

1. `calendar-query`（`VEVENT` + 时间范围）；
2. `calendar-query`（`VEVENT` + `VTODO` + 时间范围）；
3. `calendar-query`（不带时间范围）；
4. 只取 `getetag`，内容后续补取；
5. 若 `REPORT` 完全不返回资源 → 退回 `PROPFIND` 枚举 `.ics`；
6. `multiget` 失败 → 退回逐条 `GET`（有限并发）。

### ③ 数据格式归一化

| 畸形输入 | 处理 |
| --- | --- |
| `calendar-data` 里的 CRLF 被写成 XML 实体 `&#x0D;&#x0A;`（QQ 邮箱） | 先解码实体再解析 |
| 响应里没有 `resourcetype`（QQ 邮箱只给 `displayname`） | 接受 home 集合作为日历 |
| 非标准 `TZID`（`TZ08`、`CST8`、`Xmail Custome Time`） | 从 `VTIMEZONE` 读 `TZOFFSETTO`，按墙钟时间换算 |
| 相对 `href` 缺少挂载前缀（Vikunja 的 `/dav/…` 实际在 `/api/v1/dav/…`） | 用实际请求 URL 重新拼接 |
| `multiget` 必须 `Depth: 0`（企业微信用 `Depth: 1` 返回 403） | 固定用 `Depth: 0` |

### ④ 服务端差异速查

| 服务 | 关键差异 |
| --- | --- |
| **QQ 邮箱** | 无日历发现（要手填集合地址）；CRLF 用 XML 实体；集合名是不透明 ID；`~` 不能转义 |
| **企业微信** | 根路径 403 + HTML（需 `.well-known`）；忽略时间范围；`multiget` 需 `Depth: 0`；`REPORT` 里 `calendar-data` 可能 404，需逐条 `GET` |
| **Vikunja** | 只有 `VTODO`；忽略时间范围；不支持 `sync-collection`；`href` 缺挂载前缀 |
| **Nextcloud / Radicale / Baikal** | 标准实现，直接可用（Radicale 可能忽略 `If-Match`） |

### ⑤ 如果某个应用仍然读不到事件

1. 打开「高级 → 调试模式」；
2. 同步一次，然后「查看插件日志 → 导出到文件」；
3. 日志里会显示每个 `REPORT` 变体的结果（空结果 / 未返回 `calendar-data` / 资源数）与响应体，
   据此即可定位。

## 7. 常见问题

**Q：同步报错「推送事件失败（…）：更新事件失败（HTTP 500）」？**

多半是把**日程**推给了**只支持任务**的日历。Vikunja 这类服务端对 `VEVENT` 会返回 500。
插件现在会自动跳过（日志显示「该日历只支持任务，无法写入日程」）；若仍有历史遗留问题，
用「高级 → 清空同步映射记录」后重新同步。

**Q：刷新后什么都没变，或者反复请求？**

远端缓存有效期 30 秒、本地数据源 3 秒。频繁的本地编辑不会触发远端重新请求。

**Q：日历上一片空白，侧栏里却有日历？**

- 确认该日历在侧栏**已勾选**；
- 确认事件落在「同步过去/未来天数」范围内；
- 打开调试模式看日志里该日历的资源数是否为 0。

**Q：数据库同步正常跑，但一行都没写？**

检查「数据库同步 → 启用数据库同步」是否勾选。若未勾选，日志里会显示 `target=read-only`，
设置页顶部也会有醒目警告。点「读取字段」可自动启用。

**Q：删除数据库行后，再同步又出现了？**

这是**预期行为**：删除行只是删掉了本地条目，远端事件还在，下一次同步会重新拉回来。
要彻底删除请**同时删除远端事件**。

**Q：换了一个数据库，字段读不出来？**

填新数据库的块 ID 后点「读取字段」即可。插件会自动丢弃**属于旧数据库的视图 ID**并重试，
并把新读到的字段列出来；同时会清空旧的字段绑定（防止拿旧列写错数据）。重新选好列再启用即可。

**Q：密码会不会泄露？**

用「密钥名称」方式时不会（配置里只有密钥名）。用「密码」方式时密码会明文存在插件配置里，
**导出配置分享前请先改成密钥方式**。

**Q：提示「tree not found」？**

这是内核在说「这个块还没进块树索引」。绑定「插件标识」列后，插件不再写行块属性，
该报错会从根上消失。

**Q：状态栏的同步入口在哪？**

v0.6.6 起已移除右下角状态栏标识（与系统字号/颜色不一致），同步入口在**日历面板底部**与顶部栏图标。

## 8. 已知限制

| 限制 | 说明 |
| --- | --- |
| 不支持 Digest 认证 | 仅支持 Basic / Bearer |
| 重复事件编辑 | 改动会作用于**整个系列**，暂不支持「仅此一次」 |
| 提醒（VALARM） | 能解析但**不投递**，不会弹思源通知 |
| 时区数据库 | 不内置 IANA 时区表，依赖 `ical.js` 与 `VTIMEZONE`；非标准 `TZID` 用偏移量近似 |
| 代理体积上限 | 内核 `forwardProxy` 单次约 32 MiB |
| 思源文档索引上限 | 单次最多扫描 5000 个文档 |
| Radicale 类服务端 | 可能忽略 `If-Match`，并发写有覆盖风险 |
| OIDC / 2FA 账户 | Vikunja 等需改用 API Token |
| 数据库行删除 | 行是游离块，删除即删除块，请自行备份 |

> 打包结构由脚本强制保证：`scripts/zip.mjs` 写入前会校验「唯一顶层目录 + 清单在目录内 +
> 目录名与清单 `name` 一致」，`scripts/check-consistency.mjs` 也会在发布前再查一遍。

### 界面文案约定

- 高亮状态**不得使用白色文字**（深色/浅色主题下都会不可读），统一用 `--cc-highlight` + 加粗；
- 中文文案使用「」引号，英文使用 “ ”；
- 所有用户可见字符串必须走 `t()`，不允许硬编码。
